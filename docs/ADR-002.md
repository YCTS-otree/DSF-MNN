# ADR-002：交互默认混合检索，自发联想按线索升级

日期：2026-10-24。状态：采纳。

三种召回共享同一个 Recall / MemoryStore。Automatic Recall 默认 hybrid 与小字节预算；Voluntary Recall 可使用 memory_explore 显式请求 PPR；Spontaneous Association 使用低成本 lexical gate，再在总计算、时间、hop、node 与输出预算内探索 PPR。Dreaming 复用相同候选流程。没有足够线索返回 no-op，不调用外部工具，不强制形成记忆，也不自动通知用户。

实测合成 8 query/规模：100 节点 PPR Recall@5=1.0，hybrid=0.5；1k 为 .625/.5；10k 两者均 .5，图扩散未带来召回收益，且延迟略高。不能只展示小图优势，因此不把所有交互默认升级为 PPR。此结果来自词项哈希基线，不能推导真实语义模型的结论。

关联候选保存 trigger、anchor、稳定 target ID、双方预期版本、原始证据与 inference 标签。接受候选需要可信调用方的证据校验函数；仅能成为 related_to 的推断边。因果关系不由相似度、检索次数或模型自述升级。候选可不落边，反复 cue ID 幂等。当前尚无生产 DSH 回调装配。

默认预算为合作式检查：计算量是词项处理/向量维度/边更新等可解释工作单位，不是硬件指令计数。检查点之间的 SQLite 读取或本地模型推理不可被 Python API 硬抢占；Node worker 可通过 AbortSignal/超时终止子进程。Token 预算采用 UTF-8 bytes 的保守代理，不能假称精确模型分词。
