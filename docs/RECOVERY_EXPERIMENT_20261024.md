# 首次真实 Dreaming 与隔离 DSH 恢复实验

版本：1.1.0；日期：2026-10-24；设备：CPU。固定对照为 `29d7de6b3fcb2e909ea8f49436640de77db09f6d`。本报告不包含原始个人对话，私有原件保存在本机实验目录。

## 结论与适用范围

MNN 主导的分段 Dreaming、ACR 与独立 CompactionEngine 在真实备份的隔离副本上恢复了同一个 DSH Session。原始 3,901 个事件逐项相等；Self 完整系统投影不变；没有加载 Basic；正式 DSF 会话未修改或启用。原始请求曾达到输入 1,088,592 Token，加输出 8,192 后超过 1,048,576 上限。新计划的完整 Provider 预检输入为 20,025，实验上下文上限 65,536，预留输出 8,192。

这是单会话、8 个预先固定证据问题的研发结果。真实续接使用同一模型别名，但工具从原来的约 30 个收窄为 3 个只读 MNN 工具；新提问与原失败请求不同。因此 Token 降幅不能当成受控算法收益，也不能据此宣称优于 HippoRAG、A-MEM 或普通 RAG。

## 现场保护和基线先行

两份现有 `.DSF` 均经原项目 inspect 完整校验；4 个 SQLite integrity_check 通过，导出 10 个备份 Session。末尾 14 次超限失败及全部工具配对保留。备份包含状态/身份/会话，但缺完整 runtime 配置；原始 request/header 中的安全模型参数另行记录，不能宣称备份涵盖全部运行配置。

在首次历史语义 LLM 请求之前，从冻结 source ZIP 解出 v1.0.0，在新的数据库上回放相同的 3,901 个标准化事件。共享输入 SHA256：`4a0ebe5ed5592cf9f6873ad230f158c35ac70a6afbe31693acd2a3d0f0e3450e`。原始版本 API Dreaming 与 CLI association 模式均运行并分别保存。

## 配对检索结果

问题集在提取前冻结，覆盖起源介绍、角色/照片、互联网状态、账号交接、外部身份声明、转发认证边界、未答命令与超限参数。按正确 source_ref 的排名评分，不使用 LLM 自评。两边使用相同 CPU 哈希向量、k=5、2 hop、fanout=16、节点预算128；recall.py / embedding.py / store.py 与冻结源按字节相同。SQLite 复制到新评测库，查询计数不污染原结果。

| 策略 | v1 Recall@5 | 新版 Recall@5 | v1 MRR@5 | 新版 MRR@5 |
|---|---:|---:|---:|---:|
| Hybrid | 0.500 | 0.500 | 0.3125 | 0.2708 |
| BFS | 0.500 | 0.500 | 0.3125 | 0.2708 |
| PPR | 0.500 | 0.625 | 0.3125 | 0.3479 |

新版 Hybrid/BFS 的 MRR 下降，是保留的负结果。选择性 note 没有覆盖所有细节，部分聚合节点排序靠后；PPR 在此小样本找回一个额外来源，仍不构成显著性结论。

4,096 bytes 上下文中正确来源覆盖：v1 4/8，新版图谱+原文回查 7/8；G5 外部身份声明仍未进入预算内结果。这是系统功能对照，包含新增原文 BM25 回查，不能归因于图算法本身。完整逐查询排名、路径、上下文、延迟均保留。140 个保存的 evidence quote 均能在来源找到原样子串；这只能证明引用有效，不等于 140 项断言语义正确。

## 失败、修正与真实恢复

全部 native UUID 尝试保留，没有覆盖不利结果：

- 首次提交后原生 Turn 因程序化配置未使用 Volatile getter 失败；原始前缀仍完整。修正后加入原生回归。
- 后续一次运行完成但把发送者 QQ 身份混入自身；另一次恢复猜错原始命令日期。增加桥接 actor/account 显式语义、原文回查和精确事件时间后解决。
- 初始语义提取有 4 个 quote 不匹配候选，拒绝入库。精确数值审计发现另 3 条 note 包含其引用来源不支持的参数；在新数据库变体中标记 disputed、保留历史，重新巩固其余 64 条。新增写入校验，不覆写第一版输出。
- 历史 Goal 观察曾混入当前任务；现在只有 carryover layer 的活跃 Goal 进入当前续接目标。
- 早期 Node 回归曾使用错误 node_modules 路径；另一次同步 AbortError 与 Promise 测试不一致。均有后补失败记录说明，不能假称当时完整 stdout 已保存。
- 最后一次质量检查以字符串比较 6 位小数时间，误判模型返回的 3 位小数时间；改用 aware datetime 相等验证，原误判结果保留。

最新带源码捕获的原生恢复目录为 `native-7efee65f-58ed-4018-98b9-9302261dc490`。完成 4 个 assistant 消息、6 个 MNN 工具调用，turn/end=completed。实际每个续接请求输入（含缓存）分别为 15,777 / 18,567 / 19,247 / 19,740 Token；最大加 8,192 仍在实验预算内。能基于原始证据回答起源介绍、互联网仍在建、QQ 交接及 `/stauts` 的准确 observed_at。没有执行该命令或外部动作。

进程退出后通过官方持久化只读重开：3,940 个持久事件，原始 3,901 前缀完全相等，同 Session ID，当前 Self 完整相等，271 个工具调用/结果配对，最后 Turn 完成。相同机制也核对了上一份成功副本。两份原始备份和隔离 source.DSF 哈希再次一致；冻结研究材料 10 个文件、3,871 个归档成员及 tag commit 验证通过。

## 成本、实验保存与复现边界

独立语义 Provider 共保存 12 份请求收据，含连通性 probe、9 段提取、初次巩固和审计后再巩固：输入 122,492、输出 20,814，总 143,306 Token。别名实际回执为 deepseek-flash；未固定不可变权重 revision，不能宣称模型权重严格复现。所有 native 尝试合计另计输入 474,375（含缓存）和输出 4,187，26 次计量请求；与语义请求分开，失败也计入。不推算未经核对的货币费用。

原版/新版 raw SQLite、Provider 请求响应、9 段输出、旧/新计划、所有失败和成功日志、质量集与比较结果均在 `experiments/private-recovery-20261024T172636-8c594c32/`。内容不加入 Git 或发布源码；维护者应将私有保存包复制到长期备份介质。当前版本另保存源码、Python/Node 运行依赖、官方词表和逐文件校验清单。

初次提取只在运行时捕获了三个关键源码哈希，后来逆向移除已知增量恢复出完全相同 SHA256 的源文件；它是哈希验证的事后重建，不能冒充当时完整 source.zip。早期 native 尝试没有完整源码快照；最新 native 尝试已先保存显式源码副本。早期缺失日志如实列在 retrospective failures 中。

初次提取变体把 note 的 created_at 回填为来源时间，实际创建时刻应以 Provider 收据和 provenance 为准；后续代码已改为独立的记录创建时间，observed_at 保留来源时间。历史实验库不追溯改写这一字段。

尚无完整任务状态真值表，所以不报告 Carryover 完整率为 100%。12 个当前投影可解析证据，未答命令和时间精确保留，部分状态仍是 LLM 推断。没有真实神经 Embedding、LongMemEval/LoCoMo、完整 A–F、Linux 实机、线上压力/overflow 并发或生产恢复验收。

## 生产建议

建议保持正式禁用，先人工审核 Carryover 与争议 note，并补充 live 并发、取消/断电持久化、删除再导入和更广问题集。未来正式切换需要项目持有进程的停服、完整 `.DSF` 校验门禁及独立开关。保留本轮原始恢复点；MNN 失败应停止并报告，不静默切换 Basic。无需通过强制 Self 演化来验证恢复。
